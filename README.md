# NewsClaw / 新闻爪

**新闻爪抓的不是新闻，而是真正发生的变化。**

📌 最新版本：**v0.1.0**

> 发布边界：NewsClaw 不使用上游 `openbiliclaw-v*` 聚合 Release 作为自己的更新或下载渠道；当前 GitHub 仓库仅用于私有源码托管。

NewsClaw 是一个只在本机运行的独立个性化新闻 Agent。它不把文章流当成最终产品，而是把文章保存为证据，持续识别同一现实事件从 A 到 B 的客观变化，帮助一个人更快理解宏观信息、投资研究和创作选题。它拥有自己的新闻来源、产品语义、数据和配置，不依赖其他产品运行。

> 2026-08-17 已完成本机正式切换：正式服务运行在 `http://127.0.0.1:8430`，使用独立数据库、独立 `NewsClaw` 开机启动项和 DSH 2.0.0 插件。开发调试仍使用 8431，不覆盖正式运行目录。

## 核心体验

- 每天从已授权的新闻 API 和官方/自定义 RSS 获取内容；新闻采集不爬网页、不读 Cookie。
- 用户通过 DSH Agent 工具或后端 REST 明确提出研究问题时，可按需调用 Tavily
  Search，或从 1–3 个显式公开 URL 抽取相关证据；研究不会自动写入画像或推荐池。
- “事件 → 偏好 → 觉察 → 洞察 → 灵魂”五层链路继续作为**系统推断画像**，但不再冒充用户确认事实；收藏与稍后读只在本机保存，也不会自动确认任何个人记忆。
- 个人记忆是独立的用户控制层：用户手工写入，或对带来源的 AI 候选明确确认后，才会进入长期信息或当前研究；所有修改、删除、恢复都有本地版本记录。
- 首页使用“优先队列 → 单条结构化判断 → 行动/记忆”的工作台；队列按用户匹配、证据、时效和事件影响的复合优先级排序，不把正文重复铺满屏幕。
- 推荐理由回答“为什么适合你、可能影响链、后续观察点”，不输出买卖建议。
- 标题级、摘要级和正文级证据严格区分；AI 不得把标题伪装成读过全文。
- 单一来源失败只使系统进入降级，不会假装整体刷新成功。
- “今日首选”只使用北京时间当天发布的新闻，不拿旧闻凑数。刷新会先把当天新闻加入专用评估队列；即使推荐池已满，也会在当日有界预算内继续评估。新条完成推荐文案、已经可展示后，系统才替换低优先级旧条；喜欢、已推荐和正在处理的内容不会被误删。当天确实没有合格新闻时，页面显示真实空态或处理进度。
- **Phase 2 持续跟踪已经实现**：正常新闻刷新完成后，把同一批已规范化、去重的本地新闻交给后台跟踪任务，刷新本身不等待模型分析。系统先用本地规则缩小候选，再由结构化模型核验“只是相关”还是“真正发生变化”。只有实质变化进入本地时间线和未读提醒，失败只显示故障并继续有界重试；手动“立即检查”会等待真实结果，若同一观察点已有后台检查则复用那一轮，不会重复调用模型。停止跟踪只停止后续复查并保留历史，已停止项目可建立新周期而不覆盖旧记录。该流程不会自动调用 Tavily，也不会修改画像。
- **Phase 3 持久事件层已经实现**：新闻文章只作为证据，不再被当成事件本身。系统先用精确规范化的 `story_key` 确认是不是同一个现实事件，再在事件内部按“之前状态 → 现在状态 + 生效时间精度”识别同一次变化；来自不同观察点或不同来源的同一变化只增强佐证，不重复制造未读。默认变化流只允许已经发生、能说明 A→B、并且本机确实保存了足够摘要或正文证据的已确认客观变化。若两个可靠来源对同一时点给出互斥结果，事件会进入“有争议”状态，冻结当前状态并保留双方证据，直到更强证据明确解决，绝不替用户强行选边。如果合并事件时同一后续变化出现两个不同的前置变化，系统会把两条候选关系及其原始来源保存到独立账本；一次明确裁决会标记胜出关系、拒绝其他候选并解冻事件，不会把输家记录删掉。预期、市场情绪和 AI 分析继续保存为次级信息，但不会伪装成事实。旧跟踪历史、来源归属和旧版变化身份会在后台分批、可恢复地修复；旧字段声称“全文”但实际没有足够内容的记录也不能通过事实门。该真值层不会自动调用 Tavily 或修改画像。
- **Phase 3 事件档案桌面入口已经实现**：桌面 Web 把客观事件组织成“事件收件箱 → 当前变化脉搏 → 证据与持续跟踪”的主从工作台。未读、争议和主题筛选都读取同一后端真值；默认时间线显示当前安全的 `is_state_applied` 客观 A→B 变化集合，事件的标量 `current_state` 才沿一条可达状态链计算。冲突时冻结当前状态，历史分支、失效变化及裁决后的争议输家只进入可切换的审计视图，且不能重新制造未读。证据在抽屉中按需展开，不把正文重新铺满主界面。窄屏采用收件箱/详情二选一的主从切换，而不是压缩成双栏。全局未读摘要来自独立只读接口；事件收件箱续页使用带全局 revision fence 的 v3 游标，主题筛选只写入固定长度摘要而不复制原始长文本。续页期间若底层事件、变化、证据或跟踪状态已改变，服务端返回 409 要求从首屏刷新，避免重复或跳项。
- **Phase 4 个人记忆已经实现**：桌面 Web 提供“长期信息 / 当前研究 / 待你确认 / 修改记录”四区。AI 与行为链只能提出带来源的待确认候选，不能直接写入生效记忆；只有用户主动新增或明确接受才进入记忆。活动长期信息只在下一次对话型模型调用中进入有界上下文；当前研究只进入下一次推荐评估/表达上下文，普通评估、探测、画像和 Soul 重建不会收到个人记忆。浏览或管理记忆不会触发外部模型调用，删除后下一次对应调用立即失效。编辑、删除、恢复和候选接受/否定使用版本号与幂等请求收据，在同一事务追加审计历史；旧画像、旧 `validated` 和来源不明的旧结论不会自动迁移成用户已确认事实。候选若会修改已有人工记忆，必须先展示现有内容和准备写入的内容，再带目标编号和版本二次确认，不能静默覆盖。
- **Phase 5 网页/PDF 变化监控已经实现**：用户主动添加一个公开网页或 PDF 后，系统先保存首个正文基线，不制造假变化；独立调度器以后按间隔复查，先去除导航、广告、Cookie 提示、更新时间等页面噪声，再比较规范化正文。只有可核验的正文变化才在同一事务写入不可变版本、精确增删差异、既有事件档案和持久站内通知。抓取失败保留检查账本并按 1 分钟到 6 小时有界退避，最终进入“需要处理”；恢复后另发恢复消息。判断过程不调用 LLM/Tavily、不写画像或个人记忆，也不会把用户备注当成客观事实。桌面与窄屏 Web 共用一个简洁监控页，DSH 内容库和 31 个 Agent 工具复用同一真值，扩展只显示未读角标并打开本机监控页。

## 新闻来源

首批只支持已形成明确契约的入口：

- Tushare `news`、`major_news`、`cctv_news`；
- 网站主动提供的 RSS/Atom；
- 用户自己添加的 RSS/Atom。

每条文章存储媒体、技术提供方、原文链接、发布/抓取时间、正文等级、内容哈希和时效状态。

Tavily 不属于上述新闻源。它是按需研究提供方：默认使用低成本 basic Search、最多
返回 5 条（硬上限 8 条），Extract 只处理用户明确给出的公开 URL。结果与来源 URL
保存在独立本地研究账本，并按主题使用有界缓存。Phase 1 的桌面 Web 只负责 Key
管理与连接验证；手机/PWA 和浏览器扩展尚无研究按钮，也都不持有 Key。

用户主动添加的网页/PDF 监控也不属于新闻源：它不会进入推荐池或替代 Tushare/RSS，
只负责回答“这份指定文档的正文后来是否真的变了”，并把确认变化投影到既有事件档案。

## 工作流

```text
 Tushare / RSS ─→ 新闻证据 ─→ 规范化本地批次 ─→ 评估与复合排序 ─→ 完全相同事实展示防重 ─→ 判断工作台
                                      └→ 精简标题 + 原文/检索/缺失三态；原始证据不删除
                                      └→ 北京时间今日新闻 ─→ 今日专用队列 + 每日有界预算
                                                               ─→ 文案就绪 ─→ 保护用户状态后替换低优先级旧条 ─→ 今日首选
                                      │
                                      └→ [Phase 2] 到期观察点 ─→ 本地规则短名单
                                                               ─→ 结构化模型核验
                                                               ├→ 实质变化 ─→ 检查 + 证据账本
                                                               │                └→ [Phase 3] 同事务事件投影
                                                               │                     ├→ 新客观状态变化 ─→ 本地事件变化账本 + 未读
                                                               │                     ├→ 同一变化的新佐证 ─→ 增强证据，不重复未读
                                                               │                     ├→ 同时点互斥变化 ─→ 标记争议、冻结状态、等待解决
                                                               │                     ├→ 预期/情绪/分析 ─→ 次级信息，不进客观变化流
                                                               │                     └→ [Phase 3 档案页] 事件收件箱 ─→ 当前安全客观变化 ─→ 证据抽屉
                                                               │                                  ├→ 未读/争议/主题都以后端真值为准
                                                               │                                  ├→ 冲突冻结当前状态；审计视图保留旁支
                                                               │                                  └→ 窄屏主从切换，不另建客户端账本
                                                               └→ 无变化 ─→ 仅记检查历史，不通知

 行为/对话 ─→ 系统推断画像 ─→ 带来源的待确认候选 ─→ 用户接受 ─→ [Phase 4] 个人记忆
 用户主动新增 ──────────────────────────────────────────────→ [Phase 4] 个人记忆
                                                           └→ 版本化编辑 / 删除 / 恢复 / 修改记录

 判断工作台 ─→ 明确反馈 ─→ 系统推断画像
             └→ 保存/点击/反馈 ─→ 不可变判断快照 ─→ 本地历史

DSH Agent / REST 研究请求 ─→ 本地新鲜缓存或 Tavily Search/Extract
                          ─→ 可引用证据 + 独立研究历史
                          └→ 不自动修改画像、新闻候选或推荐池

用户添加公开网页/PDF ─→ 安全抓取 + 首个正文基线 ─→ 独立定时复查
                      ─→ 页面噪声过滤 + 确定性正文差异
                      ├→ 真变化 ─→ 不可变版本 + 同一事件档案 + 本机消息
                      ├→ 仅噪声 ─→ 留审计版本，不提醒
                      └→ 失败 ─→ 有界退避 / 需要处理 / 恢复消息
```

## 四个客户端

- 桌面 Web：事件工作台、推荐、当前列表筛选、内容库、网页/PDF 监控、个人记忆、系统推断画像兼容信息、对话、消息、Runtime 和完整设置；窄屏复用同一响应式监控页。
- 手机 Web/PWA：同一数据库和画像，支持下拉刷新与在线/降级/离线状态。
- 浏览器扩展：只是新闻爪侧栏客户端，不注入新闻网站、不抓页面、不读 Cookie；可显示本机监控未读角标并打开 8430 的监控页。扩展领取登录态平台任务时复用七源 source task multiplex，不另建旁路队列。
- DeepSeek Harness：真实尾部网格列，默认 380px，可调 280–560px，会话区至少保留 400px；内容库提供紧凑监控管理，31 个 Agent Bridge 工具同时覆盖新闻、按需研究与完整 P5 操作。

四端共用一个后端、主 SQLite 数据库、画像、推荐池、收藏和对话记录；按需研究证据
另存于同一私有数据目录中的独立 SQLite 账本，避免与画像和推荐库存混写。

Phase 2 的完整持续跟踪入口只放在桌面端。手机/PWA、浏览器扩展和 DSH 在本阶段仍可使用原有新闻能力，但不提供跟踪中心、变化时间线或手动立即检查入口；后续接入时继续复用同一后端真值，不另建第二套状态。

Phase 3 的事件档案真值已接入桌面 Web；手机/PWA、浏览器扩展和 DSH 仍没有独立事件工作台，也不得另建第二套状态。Phase 4 个人记忆当前同样以桌面 Web 为完整管理入口；其它客户端不能把旧画像或 AI 推断直接写成用户确认事实。所有客户端都不能自行把预测、情绪或 AI 推断升级为客观变化，也不能在证据冲突时替后台偷偷选边。

## 本地开发预览

```powershell
& .\scripts\run-newsclaw-dev.ps1 -Port 8431 `
  -RuntimeRoot "<private-runtime-directory>" `
  -SourceConfig "<existing-local-config.toml>" `
  -PythonExecutable "<python-with-project-dependencies>"
```

启动后打开 `http://127.0.0.1:8431/web`。凭据只保存在私有运行目录或环境变量，不写入源码、日志或 Agent 输出。Tavily Key 可在 NewsClaw 本机设置中保存，或用 `TAVILY_API_KEY` 作为回退；它只用于鉴权，不会混入研究查询或 URL，也不会在页面回显。

日常使用、功能和配置说明见 [NewsClaw 使用指南](docs/newsclaw-user-guide.zh-CN.md)；架构、数据合同和失败边界见 [NewsClaw 架构](docs/newsclaw-architecture.md)。

## 使用边界

- 默认仅供本人本机、非商业使用。
- Tushare 新闻权限与普通会员权限独立，启动时会逐接口验证。
- 以后如果公开、收费或展示第三方全文，必须重新取得机构和内容展示授权。
- 本版不做量化行情、券商接入、自动交易、通用网页爬虫或公网部署。只会复查用户明确添加的公开网页/PDF，并严格拒绝本机、私网、带凭据和异常跳转目标。
