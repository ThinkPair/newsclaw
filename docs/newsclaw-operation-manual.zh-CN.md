# NewsClaw / 新闻爪使用与讲解说明书

> 适用版本：NewsClaw `v0.1.0` / `588dcbe`（2026-08-31 功能修复基线）、浏览器扩展 `0.1.0`、DSH `2.2.1` / `d7bae2d`
> 适用对象：政策、金融、研究、咨询、内容分析等对信息变化敏感的个人用户

## 一句话理解新闻爪

新闻爪不是让人刷更多新闻，而是把不断出现的新材料整理成：

**什么真的变了 → 证据在哪里 → 这条变化属于哪个持续事件 → 以后还要盯什么。**

新闻浏览只是入口。事件档案、持续跟踪、本地记录和可核验的解释，才构成完整产品。

## 1. 整体工作逻辑

新闻爪把信息处理分成五个连续步骤：

1. **新材料**：从已配置的新闻 API、RSS 和用户指定的公开监控页取得材料。
2. **判断材料**：区分来源、发布时间、证据完整度、用户相关性和后续观察点。
3. **沉淀事件**：把属于同一现实事件的材料放进同一事件档案，保留当前变化、历史证据和争议。
4. **持续跟踪**：围绕明确观察点检查后续材料；只有状态真的变化才形成变化记录。
5. **本地记忆与复盘**：收藏、阅读、事件、监控版本、个人记忆和对话的账本保存在本机，之后可以继续使用。

“保存在本机”说的是长期账本，不等于所有计算都只在电脑里完成。启用远程大模型或远程向量服务后，完成当前任务所需的文章内容、问题、对话历史，以及有界的画像或个人记忆摘要，可能发送给用户自己配置的服务商。

可以把它想成下面这条链：

```text
零散新闻
  ↓
可核对的新材料
  ↓
同一事件的连续变化
  ↓
下一步需要验证的观察点
  ↓
本机长期档案与个人理解
```

## 2. 第一次使用：十分钟上手

### 第一步：确认系统在线

打开新闻爪后，先看顶栏或侧栏的状态：

- **在线**：本机后端可以连接，主要能力可用。
- **降级**：部分来源或模型暂时失败，已有内容仍可阅读。
- **离线**：本机后端未运行或地址无法连接。

状态在线不代表每一个外部来源都有新内容。需要在“设置 → 新闻源”查看每个来源的独立结果。

### 第二步：看“新材料”

新材料页是待处理队列。建议先看三件事：

1. 优先级：这条材料是否值得现在处理。
2. 主题和来源：它属于什么问题、来自哪里。
3. 证据等级：目前只有标题、摘要，还是已经取得正文。

点左侧一条材料，只是在右侧打开详情，不等于已经阅读，也不会自动改变画像。

### 第三步：核对原文

原文按钮有三种状态：

- **阅读原文**：来源提供了可确认的公开地址。
- **检索来源**：来源没有给直链，只能按媒体和标题帮你打开检索页；它不是已确认原文。
- **暂无原文**：现有数据不足，按钮不可用。

只有“阅读原文”会形成弱阅读信号。“检索来源”不会被新闻爪假装成原文，也不会自动调用 Tavily。

### 第四步：把重要内容放到正确位置

- 暂时没空读：**稍后读**。
- 想长期保留：**收藏**。
- 想验证后续变化：在“后续观察点”点 **加入跟踪**。
- 想围绕这条材料继续问：点 **聊一聊**。
- 明确相关或不相关：点 **喜欢 / 不感兴趣 / 忽略**。

收藏和稍后读不等于喜欢，也不会自动强化画像。

### 第五步：回到“事件脉冲台”

事件脉冲台回答的不是“今天有多少条新闻”，而是：

- 哪个现实事件正在变化；
- 从什么状态变成什么状态；
- 哪些证据支持这次变化；
- 是否出现互相冲突的证据；
- 下一次应该检查什么。

如果暂时没有事件，这是正常空状态，说明当前材料还没有形成可确认的持续变化。

## 3. 桌面端页面与全部主要按钮

桌面端公共入口包括：左侧六个主页面；顶栏的后端状态、关于、主题切换、手机版二维码和消息；侧栏“最近动态”的“全部”可打开完整活动记录。消息抽屉会明确区分加载、失败和空状态。“查看”会尝试打开可确认的原文，并同时确认这条通知；确认失败时消息会保留。普通新闻入口无法在所有浏览器中确认新页面是否真的打开；网页监控消息若检测到弹窗被拦截，则不会把消息当成已经处理。“忽略”只处理本机消息，失败时同样保留并可重试。

### 3.1 事件脉冲台

| 按钮或区域 | 实际作用 | 不会做什么 |
|---|---|---|
| 主题筛选 | 只看某一类事件 | 不修改画像 |
| 全部 / 未读 / 冲突 | 按事件状态筛选 | 不改变事件事实 |
| 刷新 | 重新读取本机事件档案 | 不主动调用 Tavily |
| 查看更早变化 | 继续读取该事件的历史变化 | 不把历史旁支变成当前状态 |
| 查看证据 | 打开来源、摘录和原文入口 | 不替用户判断真假 |
| 显示完整审计历史 | 查看被替代、失效或落败分支 | 不让旧分支重新成为当前状态 |
| 标为已读 | 只改变本机未读状态 | 不代表同意结论 |
| 查看持续跟踪（N）/ 从新材料建立跟踪 | 打开已有观察点，或回到新材料建立一个 | 不会自动下投资结论 |

出现冲突时，新闻爪会冻结当前状态并保留双方证据，不会为了给出一个漂亮答案而擅自选边。

### 3.2 新材料判断工作台

| 按钮或区域 | 实际作用 | 说明 |
|---|---|---|
| 顶部筛选 | 过滤当前已经加载的新材料 | 只在新材料页生效，不是全库搜索 |
| 主题标签 | 按当前已加载材料的主题筛选 | 数量是当前列表数量 |
| 媒体来源 | 按来源筛选 | 与主题筛选可同时使用 |
| 推荐队列 | 选择要在右侧查看的材料 | 选择本身不学习 |
| 今日首选 | 看北京时间当天的高相关候选 | 不用旧闻冒充今天 |
| 前一条 / 后一条 | 切换今日首选 | 不产生反馈 |
| 刷新今天 | 抓取并处理今天的新材料 | 处理失败会明确显示原因，不会无限转圈 |
| 展开原始内容 | 核对本机保存的标题、摘要或正文 | 默认折叠，减少文字墙 |
| 为什么值得看 | 展示推荐依据 | 属于解释，不是来源事实 |
| 可能影响链 | 展示可验证的传导假设 | 不等于已发生结果 |
| 后续观察点 | 给出下一步核验目标 | 可加入持续跟踪 |
| 喜欢 / 不感兴趣 / 忽略 | 提交明确反馈 | 成功后才显示完成；失败会保留原状态 |
| 收藏 / 稍后读 | 保存到本机内容库 | 不修改媒体账号 |
| 反馈一句 | 补充为什么有用或无关 | 真正保存成功后才清空输入 |
| 聊一聊 | 带着当前材料进入对话 | 对话历史保存在本机 |
| 加载更多 | 追加一批材料 | 单次请求未完成时不会重复追加 |

### 3.3 内容库

内容库包括五个区域：

1. **稍后读**：暂时没处理的材料。
2. **收藏**：长期保留的材料。
3. **持续跟踪**：围绕观察点进行后续检查。
4. **网页监控**：盯住指定公开网页或 PDF 的正文变化。
5. **历史记录**：已经打开、反馈或路过的内容。

#### 稍后读和收藏

- “打开”遵守“原文 / 检索 / 暂无”三态；没有地址时不会出现可点但没反应的假按钮。
- “移除”只从当前列表移除，不删除原新闻材料。
- 新闻来源内容当前只保存在本机，不会同步或修改任何媒体账号。

#### 持续跟踪

| 按钮 | 作用 |
|---|---|
| 立即检查 | 发起一次真实新闻刷新；发现相关线索时可能调用已配置模型完成判断，但不会调用 Tavily；同一观察点的并发重复检查会被合并 |
| 查看时间线 | 查看每次检查、证据和真正变化 |
| 标为已读 | 只清除本地未读变化 |
| 停止跟踪 | 停止以后复查，保留全部历史 |
| 重新开始 | 建立新的跟踪周期，旧周期不被覆盖 |

“检查成功但没有变化”和“检查失败”是两种不同状态。失败必须显示原因，不能被记成“没有变化”。

#### 网页 / PDF 监控

1. 粘贴一个公开网页或 PDF 地址。
2. 首次检查建立 V1 基线，不制造假变化。
3. 以后只比较清理杂项后的正文；系统会按正文提取规则尽量过滤导航、广告、分享栏等噪声，但不能保证所有动态网页都能准确抽取。
4. 真正变化会增加版本、进入事件证据并生成本机消息。

| 按钮 | 作用 |
|---|---|
| 添加监控 | 保存目标并建立首次基线 |
| 立即检查 | 复用同一轮检查，避免并发抓取 |
| 暂停 / 恢复 | 控制以后是否自动复查 |
| 版本记录 | 查看每次正文校验摘要、差异和失败 |
| 事件档案 | 有真实变化事件后才可进入；首次基线时会明确显示“尚无事件” |
| 移除 | 从列表移除目标，但历史版本与证据仍保留 |

PDF 必须能公开访问并能直接提取文字。加密 PDF、纯扫描件和需要文字识别的文件当前不支持；单个文件上限 50 MB、1000 页，并受抓取和解析超时限制。

### 3.4 个人记忆

个人记忆和系统画像不是同一件事：

- **画像**：系统根据行为和对话形成的保守理解。
- **个人记忆**：用户主动写入或明确确认、希望长期保留的信息。

个人记忆包含：长期信息、当前研究、待你确认、修改记录。

| 按钮 | 作用 |
|---|---|
| 新增记忆 | 主动写入长期信息或当前研究 |
| 修改 | 产生新版本，不覆盖审计历史 |
| 删除 | 使该版本不再参与后续上下文 |
| 恢复这条记忆 | 从修改记录恢复一个历史版本 |
| 确认并记住 | 把待确认内容变成有效记忆 |
| 先修改 / 修改后确认 | 先由用户改写，再正式写入 |
| 不记住 | 记录这次拒绝；完全相同的规范化内容不会再次成为候选，语义相近但改写后的内容仍可能出现 |

只有主动新增或明确接受才能进入个人记忆。AI 置信度高、重复出现或画像推断都不等于用户确认。

### 3.5 聊聊口味 / 对话

- 可以从空白对话开始，也可以从某条新闻、事件或消息带上下文进入。
- 发送过程中按钮会暂时锁定，连续回车不会写出两轮重复对话。
- 发送失败时，草稿会回到原来的输入框，不会丢到另一个页面。
- 待确认的兴趣、避雷和记忆候选必须由用户明确处理。

### 3.6 设置

实际页签是：**模型、新闻源、调度、通用、前端、日志**。

- 模型：配置模型实例、链路测试、Embedding（向量理解）和网络代理。
- 新闻源：管理数据接口和 RSS/Atom（网站订阅流）。
- 调度：设置刷新节奏，以及浏览器关闭后后端继续运行还是暂停。
- 通用：局域网访问密码、自启动和整机迁移。
- 前端：主题与显示偏好。
- 日志：查看日志位置和运行诊断。

#### 新闻源

- 启用 / 停用：下一轮刷新生效。
- 验证全部来源：逐来源检查权限、网络、空结果和数据新鲜度。
- 立即刷新：创建一轮真实新闻刷新任务。
- RSS 最近内容明显陈旧时会显示“陈旧 / 降级”，不会继续用绿色“健康”误导用户。

#### Tavily 按需研究

桌面设置页只负责保存或删除 Tavily Key，并做不消耗研究额度的连接验证；`Search` 和 `Extract` 不是设置页按钮。配置完成后，在 DSH 中和 Agent（正在协作的 AI 助手）对话，明确要求联网检索或抽取指定 URL，才会使用：

- `Search`：围绕一个明确问题检索公开资料。
- `Extract`：从用户指定的 1–3 个公开地址抽取证据片段。

它不会成为后台新闻源，不会自动搜索每条新闻，也不会把搜索词写入画像。研究问题和 URL 会发送给 Tavily，因此不要包含私人信息、邮箱、手机号、本机路径或任何密钥。

#### 保存设置

保存过程中会分别核对通用配置、新闻设置和来源设置。若只有一部分成功，页面会明确告诉你哪些已生效，并重新读取本机状态；不会笼统显示“全部失败”或“全部成功”。

“通用 → 迁移 → 导出全部信息”会包含 API Key、Tushare Token、画像和历史，当前迁移包**没有加密**。它只能保存在可信设备上；迁移完成后应删除不再需要的副本。

## 4. 手机 Web / PWA

手机端适合快速阅读和处理，不是桌面端全部专业能力的缩小复制。

当前主要页签：推荐、内容库、画像、对话。

- 推荐卡默认只显示标题、来源、时效、标签和简短判断；详细解释按需展开。
- 铃铛合并新闻通知、兴趣探针和网页 / PDF 监控变化。
- “换一批”失败时保留当前内容并显示失败原因。
- 画像标签删除会提供短时撤销；保存失败会在当前字段显示。
- 新闻源入口叫“查看新闻源状态”，它用于验证和刷新，不假装可以在手机端完成全部配置。

事件档案、个人记忆和完整网页监控管理仍以桌面 Web 为主。PWA 当前是可安装的本机网页入口，不等于离线 App：断网后不能保证离线阅读，也没有系统级后台推送。

打开方式：从电脑顶栏点“手机版”扫描二维码。默认服务只绑定 `127.0.0.1` 时，二维码会提示仅限本机，手机不能直接访问；确需同一局域网使用时，应按部署说明绑定局域网地址、放行所需防火墙规则，并优先在“设置 → 通用”启用局域网访问密码。不要把没有访问保护的新闻爪直接暴露到公网。

## 5. 浏览器扩展

浏览器扩展是本机新闻爪的侧栏入口：

- 连接地址只允许 `127.0.0.1` 或 `localhost`。
- 不读取 Cookie、不注入新闻网页、不自动抓取当前标签页。
- 推荐、内容库、画像和对话复用同一套手机界面和本机数据。
- 网页监控接口临时失败时会保留入口并显示降级，不会把功能整个隐藏。
- “打开完整版”进入桌面 Web。

如果显示离线，先确认电脑端新闻爪正在运行，再到扩展连接设置核对地址。

## 6. DSH 桌面 AI 助手插件与 Agent 工具

DSH 侧栏适合在和 Agent 协作时随手查看新闻爪。它与网页端共用同一个已配置的本机 NewsClaw 后端和数据库（默认端口 8430），不会另存一套画像或内容库。

当前 Agent 工具分为：

- 推荐与运行状态；
- 反馈与今日首选；
- 对话与探针；
- 画像与本地内容库；
- Tavily 按需搜索与证据提取；
- 网页 / PDF 监控管理。

共 31 个工具。反馈、画像修改、监控创建和立即检查等关键操作支持安全重试；对话按轮次去重；收藏等集合式操作重复执行不会产生多份记录。这里的“安全重试”就是：网络超时后再次执行同一动作，不应重复记账或把同一个请求改成另一种操作。

## 7. 怎么理解页面里的判断

### 事实、解释和观察点

- **来源事实**：媒体、标题、正文摘录、发布时间、原文地址。
- **系统解释**：为什么值得看、可能影响链、主题和故事线。
- **后续观察点**：以后需要用新证据验证什么。

解释可以帮助理解，但不能冒充来源事实。影响链是待验证假设，不是预测已经实现。

### 优先级和证据等级

优先级回答“现在是否值得处理”；证据等级回答“目前掌握了多少原始信息”。

- 高优先级不等于高可信。
- 正文级不等于结论正确。
- 标题级材料可以重要，但分析必须保持保守。

### 画像和个人记忆

- 喜欢、不感兴趣、忽略、明确评论和对话确认可以影响画像。
- 收藏、稍后读、网页监控和顶部筛选不会自动改变画像。
- 个人记忆只接受用户主动写入或明确确认。

## 8. 四个典型使用场景

### 场景一：政策变化跟踪

1. 在新材料中核对政策原文或权威来源。
2. 把“配套细则何时发布”“哪些地区先执行”等写成观察点。
3. 加入持续跟踪。
4. 把正式政策页加入网页监控。
5. 后续变化进入同一事件档案，保留版本与证据。

### 场景二：行业与公司研究

1. 先用主题和来源缩小当前材料。
2. 查看事实、影响链和失效条件。
3. 收藏核心证据，稍后读长文。
4. 对关键公告页或 PDF 建立监控。
5. 在对话里要求新闻爪区分“已知事实、系统推断、仍需验证”。

### 场景三：验证一个个人判断

不要让系统简单给判断打分。把判断拆成多个可以被新证据改变的观察点，例如供给、需求、政策、资金和替代变量；每个观察点分别跟踪。最终复盘时看哪些证据真的改变了原状态，而不是只统计支持和反对新闻数量。

### 场景四：建立长期个人研究记忆

1. 在“当前研究”写下正在研究的问题和范围。
2. 在“长期信息”只保存稳定且以后仍有用的事实或偏好。
3. 定期处理“待你确认”。
4. 从“修改记录”复盘何时改变过研究方向。

## 9. 常见问题

### 点刷新后为什么没有新内容？

可能是来源本轮没有新材料、来源降级、今天的材料还在处理中，或新材料没有达到展示条件。页面会区分“正在处理、处理失败、来源陈旧、本轮无数据”，不应只表现成按钮没反应。

### 为什么有的新闻没有原文链接？

部分数据接口只返回媒体名、标题或正文，没有公开 URL。新闻爪会显示“检索来源”，而不是编造一个原文链接。

### 为什么同一事件看起来有多条材料？

同一事件可以包含多个不同事实维度或后续更新。新闻爪只折叠完全重复的展示记录，不会为了界面整洁而删除数字、时间、主体或结论已经变化的证据。需要连续理解时，应在事件档案中看它们的关系。

### 为什么“今日首选”不是二十条？

二十是最多展示数量，不是必须凑满。当天只有十四条合格内容时，展示十四条比用旧闻填满更可信。

### 升级后手机页为什么可能短暂空白？

当前版本会让入口页每次核对最新发布编号，并让同一版的脚本一起加载，避免新旧文件混用。若升级后仍看到空白页，先关闭这个新闻爪页面再重新打开；如果仍未恢复，再确认电脑端后端在线。不要长期依赖浏览器强制刷新作为日常操作。

### 关闭浏览器后还会工作吗？

取决于“设置 → 调度”里的浏览器关闭行为、本机后端是否仍在运行，以及自启动是否正常。设置为继续运行时，关闭网页后新闻刷新、持续跟踪和网页监控可以继续；设置为暂停或后端已退出时不会继续。网页本身只是查看和操作界面。

### 新闻爪会自动交易吗？

不会。它不连接券商、不自动下单，也不输出仓位、目标价或买卖指令。它提供的是材料、变化、证据、解释和后续验证。

## 10. 数据、隐私、许可与安全边界

- 数据库、画像、个人记忆、事件、监控版本和对话账本默认保存在本机；这不等于所有计算都在本机完成。
- 使用远程大模型或远程向量服务时，当前任务所需的文章内容、问题、对话历史，以及有界的画像或个人记忆摘要，可能发送给用户配置的服务商。敏感内容应使用可信服务或本地模型。
- 新闻数据接口（API）、RSS/Atom、用户指定的公开监控页和用户明确发起的 Tavily 研究都是外部数据入口。
- API Key 只保存在本机私有配置中，页面只显示配置状态、不回显明文；但“导出全部信息”的未加密迁移包会包含密钥、Token、画像和历史。
- 不要把私人资料、密钥、本机路径、邮箱或手机号放进 Tavily 查询。
- 网页监控拒绝本机地址、内网地址、带账号密码的 URL 和不安全跳转。
- NewsClaw 当前按个人本地、非商业用途使用。公开展示、收费服务、客户交付或第三方全文再分发前，必须分别核对 NewsClaw、内容来源和 Tushare 的许可；产品能读取内容，不等于已经取得展示或再分发权。
- 新闻爪是信息理解工具，不替代法律、财务、投资或医疗专业意见。

## 11. 推荐的日常节奏

### 每天 5–10 分钟

1. 看事件脉冲台里的新变化和争议。
2. 处理少量高优先级新材料。
3. 把真正重要的内容收藏或加入跟踪。
4. 清理消息中的监控变化和待确认项。

### 每周 20–30 分钟

1. 复盘持续跟踪是否产生真正变化。
2. 查看事件审计历史和失效分支。
3. 检查画像是否被误解。
4. 处理个人记忆候选和研究方向。
5. 查看新闻源健康、陈旧来源和失败记录。

新闻爪的价值不在于一天刷完多少条，而在于一个月后仍能回答：**这件事最初是什么状态、后来哪里变了、证据是什么、自己的判断又是怎样修正的。**
