# NewsClaw / 新闻爪全功能深度审计与闭环验收

> 审计日期：2026-08-31
>
> 审计对象：桌面 Web、手机 Web / PWA、浏览器扩展、DSH 插件、8430 本机后端、调度与本机数据
>
> 功能基线：NewsClaw `v0.1.0` / `588dcbe`；浏览器扩展 `0.1.0`；DSH `2.2.1` / `d7bae2d`
> 说明：以上提交均已落到本机正式版本；远程 GitHub 尚未推送。

## 1. 最终结论

本轮按“入口可见 → 操作可用 → 后端真实执行 → 失败可见 → 重试不重复 → 跨端口径一致 → 数据可恢复”的完整链路检查，而不是只看按钮能否点击。

审计共发现并修复六类核心问题：

1. **今日刷新状态失真**：已有候选完成评估，却因 SQL 参数顺序错误没有进入推荐池，页面可能长期显示处理中。
2. **成功提示早于真实结果**：个别反馈、设置、通知和移动端操作在后端失败时仍可能给用户成功感。
3. **跨端能力缺口**：手机消息遗漏网页监控变化；DSH 增加监控能力时遗漏了 Tavily Search / Extract。
4. **来源和原文表达不严谨**：陈旧 RSS 仍显示健康；没有直链的内容缺少“检索来源 / 暂无原文”状态。
5. **焦点、恢复和重复提交不完整**：抽屉、对话、移动菜单、画像撤销等路径在失败或重绘后可能丢焦点、丢草稿或重复执行。
6. **移动端升级缓存混版**：正式切换后的真实浏览器复验发现，新入口脚本可能引用浏览器缓存里的旧依赖，导致整个手机页空白。现已改为整张模块依赖图使用同一发布编号，并收紧 HTML、版本化资产和旧静态地址的缓存规则。

第 6 项是本轮唯一实际复现到的整页不可用级问题，已在正式 8430 修复并用全新浏览器页再次验证。未发现会直接破坏正式 SQLite 数据的故障。

修复后，新闻爪仍坚持原定位：**识别真正发生的变化，核对证据，把变化放回持续事件，并把用户明确选择的历史保存在本机。**

## 4. 后端和数据逻辑

### 4.1 今日刷新与候选入池

旧实现把数据库查询的范围参数和排序参数按相反顺序传入，造成已评估候选无法进入“今日首选”。本轮已修正参数顺序，并同时收紧：

- 推荐池完成收敛后再做原始数据裁剪；
- 批次状态按仍在评估、已就绪、降级或阻塞判断；
- 历史已评估记录不再让今天永久显示处理中；
- 失败保留明确原因，不用无限加载掩盖错误。

### 4.2 并发、幂等和故障恢复

- 持续跟踪增加任务代际校验，旧执行者不能覆盖新执行者结果。
- 网页监控捕获通用运行异常，失败进入可重试终态，不遗留永久运行中。
- 个人记忆重复请求返回第一次回执，不把旧请求绑定到当前对象。
- 通知未知 ID 返回真实失败，不伪造已确认。
- 手机画像撤销在部分失败后保留剩余动作，可继续执行。

### 4.3 来源健康与数据完整性

- 来源健康同时检查网络和内容新鲜度；陈旧 RSS 显示降级。
- 通用运行时间与新闻运行状态使用同一最后刷新时间。
- 正式五个 SQLite 数据库均执行只读 `PRAGMA quick_check`，结果为 `ok`；外键问题均为 0。
- 正式数据未清空、未重建、未写入演示事件。

### 5.3 真实页面操作复验

使用 Codex 应用内浏览器执行以下真实页面流程：

1. 桌面新材料：主题筛选后数量变为 3 / 20；刷新按钮请求期间禁用，完成后恢复。
2. 来源入口：无直链材料显示“检索来源”，打开的是带媒体和标题的检索页，不冒充原文。
3. 内容库网页监控：空状态正确；未输入 URL 时主按钮禁用。
4. 个人记忆：新增表单打开后焦点进入表单，取消后焦点回到入口。
5. 消息抽屉：对话框语义、焦点锁、Escape / 关闭和焦点归还正常。
6. 设置：新闻源页显示当前真实健康状态；立即刷新新闻可观察请求中和完成态。
7. 手机端：390 × 844 全新页面成功加载；四个主路由均可进入；“查看解读”只展开详情，不改变页面地址。
8. 手机缓存故障复验：先复现新旧模块混用造成的空白页，修复后用全新页确认无控制台或页面错误。

## 7. 剩余产品改进，不属于本轮故障

- 用真实长期事件数据继续验证事件脉冲台、内容库、跟踪和个人记忆之间的复盘效率。
- 把同一事件中的多条材料按时间、角色和事实变化组织，进一步降低“像重复新闻”的感受。
- 为政策与金融从业者设计更紧凑的变化摘要，但不把模型推断伪装成客观事实。
- 只有在明确手机端的长期使用场景后，再决定是否增加完整事件管理或真正离线能力。
