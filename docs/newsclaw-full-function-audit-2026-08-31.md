# NewsClaw / 新闻爪全功能深度审计与闭环验收

> 审计日期：2026-08-31  
> 审计对象：桌面 Web、手机 Web / PWA、浏览器扩展、DSH 插件、8430 本机后端、调度与数据存储  
> 审计原则：不只检查“能不能点”，同时检查按钮结果、失败反馈、数据写入、重复请求、刷新状态、跨端一致性和后续可恢复性。

功能修复基线：NewsClaw `40c1b2a`（手机/扩展首轮）、`ff54919`（桌面）、`f9d5fe2`（后端）、`3b784f0`（手机恢复性复审）；浏览器扩展 `0.1.0`；DSH `2.2.1` / `d7bae2d`。这些是可定位的功能提交，不代表已经同步到远程 GitHub。

## 1. 结论摘要

本轮审计没有发现会直接破坏本机数据库的 P0 问题，但发现了一组会让用户误判“已经成功”“仍在处理”或“没有新内容”的 P1 闭环问题。核心问题集中在五类：

1. **今日刷新状态失真**：已有候选完成评估，却因数据库参数顺序错误没有进入推荐池，页面长期停在处理中。
2. **前端成功提示先于真实结果**：个别反馈、设置和通知操作在后端失败时仍可能给出成功感。
3. **跨端能力不一致**：手机消息没有合并网页监控变化，DSH 增加监控工具时遗漏了 Tavily 两个研究工具。
4. **来源与链接表达不严谨**：陈旧 RSS 仍显示健康；没有原文地址的内容缺少明确的“检索来源 / 暂无原文”三态。
5. **键盘、焦点和重复提交边界不完整**：抽屉、对话、移动菜单等组件缺少统一关闭和单次提交保护。

修复后的产品口径保持不变：新闻爪不是制造更多新闻，而是帮助用户识别变化、核对证据、持续跟踪同一事件，并在本机保留可复盘的历史。

## 2. 审计范围与证据边界

### 2.1 已覆盖

- 桌面端 6 个主入口：事件脉冲台、新材料、内容库、个人记忆、聊聊口味、设置。
- 内容库 5 个分区：稍后读、收藏、持续跟踪、网页监控、历史记录。
- 顶栏搜索、主题与媒体筛选、今日首选、刷新、消息抽屉、关于、二维码、主题切换。
- 手机端推荐、内容库、画像、对话、消息抽屉、来源状态和卡片反馈。
- 浏览器扩展连接设置、离线 / 降级状态、完整版入口和移动界面复用。
- DSH 插件的推荐、反馈、画像、内容库、研究和网页监控工具注册。
- 8430 后端 API、刷新调度、发现候选、推荐池、通知、来源健康、事件、监控、个人记忆和 SQLite 完整性。
- 自动化测试、接口契约测试、静态检查、真实本机页面与本机数据库只读核验。

### 2.2 证据限制

- 正式库在审计时事件、个人记忆和网页监控均为空，因此这些非空状态主要用隔离测试数据和自动化用例验证，不向正式库写入演示记录。
- Tavily 未配置真实密钥，本轮只验证开关、工具注册、参数保护与失败表达，不发起付费外部研究。
- 手机 Web 当前不是离线 App，没有 Service Worker 和系统级推送；这是产品边界，不记为故障。
- 正式服务默认只绑定 `127.0.0.1`；本轮没有把服务开放到局域网，因此不把真实手机跨设备访问计为已验证。
- Playwright 在当前开发环境未安装；桌面浏览器自动化模块没有执行。页面主流程由合同测试、本机应用浏览器和同视口截图复核覆盖。
- 浏览器扩展当前正式测试命令只执行薄客户端合同文件的 8 个用例。仓库中 123 个旧架构测试文件不在该命令内，不构成本轮通过证据。
- 尚未在 iOS、Android 或独立 Chrome 真机模拟弹窗拦截、操作系统级焦点切换和断网撤销；相关边界由代码合同覆盖，不能表述成真机通过。
- 同一事件可以保留多条事实不同的材料。本轮只折叠完全重复展示，不用简单标题相似度删除证据。
- 本轮验证产品能力，不替代内容许可审查。公开展示、收费服务、客户交付或第三方全文再分发前，仍需分别核对 NewsClaw、来源媒体和 Tushare 的许可。

## 3. 逐入口功能与按钮审计

### 3.1 事件脉冲台

| 检查项 | 预期闭环 | 审计与处理 |
|---|---|---|
| 主题、未读、争议筛选 | 只过滤事件，不改画像 | 通过 |
| 变化与证据展开 | 当前变化、来源和审计历史可区分 | 通过；空库显示明确空状态 |
| 标记已读 | 只更新本地未读状态 | 通过 |
| 事件入口 | 无事件 ID 时不可产生死跳转 | 已补空 ID 禁用与说明 |
| 刷新 | 重新读取事件档案，不暗中调用搜索 | 通过 |

### 3.2 新材料判断工作台

| 检查项 | 发现的问题 | 修复后的闭环 |
|---|---|---|
| 顶部搜索 / 筛选 | 离开新材料页后仍可影响隐藏队列 | 只在新材料页显示并生效 |
| 推荐队列 | 卡片切换、主题和媒体筛选 | 选择本身不学习；筛选可组合 |
| 今日首选 | 刷新长期停在处理中 | 修复候选入池参数，状态区分处理、失败、无数据与完成 |
| 前后切换 | 边界状态 | 首尾按钮正确禁用，不产生反馈 |
| 原文入口 | 无直链时按钮可能像死按钮 | 明确区分“阅读原文 / 检索来源 / 暂无原文” |
| 喜欢、无关、忽略 | 个别路径先显示成功 | 只有 API 确认后才更新界面；失败可重试 |
| 收藏、稍后读 | 无链接的已保存卡片入口不闭环 | 复用原文三态，不再保留假链接 |
| 聊一聊、反馈一句 | 连续提交可能重复；失败草稿回错输入框 | 单次请求锁；原位置恢复草稿 |
| 加载更多 | 并发重复追加 | 请求中禁用，完成后恢复 |

### 3.3 内容库

| 分区 | 审计重点 | 结果 |
|---|---|---|
| 稍后读 / 收藏 | 打开、移除、来源三态 | 闭环；移除不删除原材料 |
| 持续跟踪 | 立即检查、时间线、停止与恢复 | 检查失败与“成功但无变化”分开 |
| 网页监控 | 添加、首次基线、立即检查、暂停、版本、事件、移除 | 无事件时禁用事件入口；并发检查给出忙碌状态 |
| 历史记录 | 分页与重复加载 | 修复重复分页保护 |
| 五个页签 | 窄窗口换行混乱 | 调整布局，保持入口可识别 |

### 3.4 个人记忆

| 检查项 | 预期闭环 | 结果 |
|---|---|---|
| 主动新增 | 用户确认后写入版本 | 通过 |
| 编辑 | 产生新版本，保留历史 | 通过 |
| 删除 | 后端成功后从有效上下文移除 | 手机端补失败反馈与安全恢复 |
| 候选接受 / 拒绝 | 必须显式确认 | 通过 |
| 延迟重复请求 | 返回原始回执，不随当前对象漂移 | 纳入后端幂等修复与测试 |

### 3.5 对话

| 检查项 | 发现的问题 | 修复后的闭环 |
|---|---|---|
| 普通发送 | 连续回车可能提交两次 | 单次飞行保护 |
| 带新闻 / 事件上下文 | 来源上下文可核对 | 通过 |
| 失败恢复 | 抽屉失败可能恢复到主输入框 | 恢复到发起请求的原输入框 |
| 候选兴趣 / 记忆 | 未确认内容不得成为正式记忆 | 通过 |

### 3.6 设置与系统状态

| 检查项 | 发现的问题 | 修复后的闭环 |
|---|---|---|
| 保存设置 | 多个配置域部分成功时只显示统一失败 | 显示每一域结果并重新读取真实状态 |
| 来源验证 | 陈旧 RSS 仍显示健康 | 增加新鲜度判断，陈旧来源显示降级 |
| 立即刷新 | 刷新卡住 | 修复发现候选入池与批次状态 |
| 运行时间 | 通用 `last_refresh` 可能停留旧值 | 与新闻运行状态对齐 |
| Tavily | 不应成为后台新闻源 | 桌面只管理 Key 和验证连接；Search / Extract 只在 DSH Agent 或后端接口按需调用，未配置时诚实提示 |
| 通知 | GET 失败可能渲染成“没有消息” | 增加加载、失败和重试状态 |

### 3.7 手机 Web / PWA

| 检查项 | 发现的问题 | 修复后的闭环 |
|---|---|---|
| 推荐卡 | 文字密度高 | 默认保留关键信息，详细解释按需展开 |
| 换一批 | 异常被吞掉 | 保留当前内容并显示失败原因 |
| 消息 | 漏掉网页 / PDF 监控变化 | 合并新闻、探针和监控通知 |
| 画像删除 | 立即消失且失败无提示 | 后端确认、失败恢复并提供短时撤销 |
| 抽屉 / 评论 | 缺少对话框语义和焦点管理 | Escape、焦点锁定、关闭后归还焦点 |
| 来源入口 | 名称像配置入口 | 改为“查看新闻源状态” |
| 视觉背景 | 未定义颜色变量导致透明 | 使用现有设计令牌修正 |

### 3.8 浏览器扩展

| 检查项 | 发现的问题 | 修复后的闭环 |
|---|---|---|
| 本机连接 | 仅允许 localhost / 127.0.0.1 | 通过 |
| 离线 / 降级 | 监控 API 失败会把入口隐藏 | 保留入口并显示降级 |
| 连接对话框 | 键盘和焦点闭环不足 | 补对话框语义、Escape 和焦点归还 |
| 旧测试 | 大量用例仍假定旧弹窗架构 | 清理当前迁移范围内的过期断言 |

### 3.9 DSH 插件 / Agent 工具

| 检查项 | 发现的问题 | 修复后的闭环 |
|---|---|---|
| 工具完整性 | 增加 7 个监控工具时遗漏 2 个 Tavily 工具 | 恢复 Search / Extract，共 31 个工具 |
| 画像修改 | 缺少稳定请求 ID | 画像编辑必须携带请求 ID；结果不确定时只允许同 ID、同内容重试，同 ID 换动作会被拒绝 |
| 后端地址 | 与桌面 Web 共用 8430 | 通过 |
| 能力边界 | 研究不应自动运行 | Tavily 仅由用户或 Agent 明确调用；对话用轮次 ID 去重，集合式收藏靠唯一约束防重复，不笼统宣称所有写操作都有请求 ID |

## 4. 后端与数据逻辑审计

### 4.1 今日刷新候选入池

数据库查询中的占位符顺序是“范围条件在前、优选来源排序在后”，旧实现却把参数按相反顺序传入。结果是已有候选明明完成评估，查询仍返回 0，推荐池无法补足，批次一直显示处理中。

本轮修复参数顺序，并补三层保护：

- 推荐池补足后再做原始数据裁剪，避免先收敛后又被裁掉；
- 批次状态根据“仍在评估 / 已就绪 / 降级 / 阻塞”判断，不把历史已评估记录永久当作处理中；
- 失败时保留明确原因，不用无限转圈掩盖错误。

### 4.2 并发与租约

- 跟踪任务的租约增加代际 / 围栏校验，旧执行者不能覆盖新执行者结果。
- 网页监控捕获通用运行错误，任务会进入失败与可重试状态，不会一直显示运行中等待租约过期。
- 写操作保持请求 ID 幂等，网络超时重试不会制造重复学习、重复通知或重复监控记录。
- “立即检查”会发起真实新闻刷新，发现相关候选时仍可能调用已配置模型完成判断；它不调用 Tavily，同一观察点的并发检查会被合并。

### 4.3 通知与来源健康

- 桌面和手机统一使用按文章 ID 确认的通知接口；未知文章不能伪造成功。
- RSS 健康同时检查连接和内容新鲜度；多年未更新的源显示陈旧 / 降级。
- 通用运行时间与新闻运行状态对齐，避免一个页面显示今日、另一个页面仍显示旧日期。

### 4.4 数据完整性

- 正式数据库执行 SQLite `quick_check`。
- 主库外键问题为 0。
- 正式数据只做只读审计和正常迁移，不清空、不重建，也不写入演示事件。

## 5. 验收口径

最终交付必须同时满足：

1. 所有 P1 闭环问题有代码修复和回归用例。
2. 正式 8430 运行修复后的版本，健康接口可用。
3. 今日刷新不再永久停在处理中；失败、无数据和完成可区分。
4. 桌面、手机、扩展和 DSH 对来源、通知、Tavily 与写操作的口径一致。
5. 修改前后页面使用同一视口和同一状态比较，并完成截图复核。
6. 文档、架构、模块说明、变更日志和本说明书与代码一致。
7. 已知 P2 产品边界和正式空数据限制被明确记录，不假装已通过真实非空生产样本。

## 6. 产品层面的剩余改进

以下不是本轮故障修复，不应用临时 UI 拼补替代产品设计：

- 在事件档案中把同一事件的多条事实按时间和角色组织，进一步降低队列重复感。
- 为政策与金融从业者设计“变化摘要”，让用户先看变化，再按需展开证据和解释。
- 在有足够真实事件数据后，验证事件脉冲台、内容库和个人记忆之间的长期复盘效率。
- 明确手机端是否需要完整事件 / 监控管理，以及是否值得增加真正离线能力。
