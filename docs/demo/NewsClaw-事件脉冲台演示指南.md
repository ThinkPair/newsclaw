# NewsClaw 事件脉冲台演示指南

这份演示只证明当前已经完成的能力：**把多篇外部材料归入同一事件，提取已经发生的客观 A→B 变化，把证据和旧版本留在本地，并在可靠材料互相冲突时冻结当前状态。**

它不演示预测、投资建议、完整个人记忆、网页/PDF持续监控或可靠通知；这些能力不能在现阶段对外宣称已经完成。

## 安全边界

- 演示端口固定为 `8431`；正式版继续使用 `8430`。
- 演示服务使用一次性的独立目录、独立 `config.toml` 和独立 SQLite；不读取正式配置、正式 SQLite、环境凭据、浏览器 Cookie 或任何用户画像。
- 不启动新闻源、调度器、LLM、Embedding、自动启动或后台同步。
- 事件列表、证据链、历史版本、冲突冻结和“标为已读”全部经过正式版相同的 API 与数据库逻辑；关闭演示窗口后一次性数据库会被清理，下次启动自动复原。
- 顶部状态始终显示“演示环境 · 正式库未连接”，避免把演示样本误认为正式历史。

## 演示数据口径

1. **LPR 事件**：回放 2024 年2月、7月、10月公开历史材料。来源链接分别指向中国货币网和中国人民银行。它不是实时行情。
2. **存款准备金率事件**：回放中国人民银行 2024 年货币政策执行报告中的公开历史事实。它不是实时政策提醒。
3. **先进制造业补贴比例**：纯合成冲突样本。事件标题、主题、来源和正文均显式标注“演示”或“非真实来源”，只用于证明“冲突时冻结、不替用户猜答案”的产品逻辑。

## 启动与停止

双击 `scripts/start-newsclaw-event-demo.cmd`，看到下面这行后，在浏览器打开 `http://127.0.0.1:8431/web/`：

```text
NewsClaw isolated SQLite demo: http://127.0.0.1:8431/web/
```

关闭命令窗口或按 `Ctrl+C` 即停止。演示运行期间“标为已读”会真实写入隔离 SQLite；演示进程停止后，隔离数据自动清理，正式历史不会发生变化。

## 三分钟演示顺序

### 0:00—0:20：先讲问题

停在三栏事件脉冲台：

> 政策和金融从业者真正怕的，不是少看一条新闻，而是同一件事已经变化，自己却没有发现。

### 0:20—0:50：事件不是文章

点击“贷款市场报价利率（LPR）调整”。

> NewsClaw 没有把三份公告当成三条孤立新闻，而是把它们归入同一个持续事件。新闻是证据，事件才是长期对象。

### 0:50—1:20：只展示客观变化

指向中栏的 A→B：

> 系统先回答最小但最重要的问题：原来是什么，现在变成了什么，何时生效，我们何时发现。预测、情绪和投资建议不进入这条事实时间线。

### 1:20—1:50：证据可以反查

点击变化，展开右栏证据：

> 每个变化都能回到来源、发布时间和本机保存的证据快照。证据不完整时，系统也必须明确说不完整。

### 1:50—2:20：历史不会被覆盖

点击“显示完整审计历史”：

> 新公告不会把旧状态擦掉。默认只看当前有效事实，需要复盘时再打开完整历史，看到这件事一路怎样变化。

### 2:20—2:45：冲突不自动裁决

切换到“【演示冲突样本】先进制造业补贴比例”，再点两条冲突证据：

> 这里是明确标注的合成演示。当两份足够可靠的材料互相冲突时，NewsClaw 不猜赢家，而是冻结当前状态，把双方证据都留给用户核验。

### 2:45—3:00：收口

> NewsClaw 抓的不是新闻，而是真正发生的变化。它把外部材料变成可持续、本地保存、能够纠错和反查的个人事件档案。

## 对外表达禁区

- 不说“全网实时覆盖”“绝不漏报”“AI 自动证明来源真实”。
- 不把历史回放说成当天实时政策。
- 不把合成冲突说成真实政策。
- 不说“预测未来”“保证决策正确”“帮助赚钱”。
- 不虚构用户数、营收、客户、专利、合作或融资。
- 应说明：项目建立在开源底座之上，NewsClaw 的事件真相层、持续跟踪和事件脉冲台是当前新增的产品能力。
