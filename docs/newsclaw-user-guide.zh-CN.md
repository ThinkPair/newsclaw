# NewsClaw / 新闻爪使用指南

## 1. 它到底是什么

新闻爪是一个独立、本机运行、由个人画像驱动的新闻理解 Agent。它每天从已授权的新闻 API 和网站主动提供的 RSS/Atom 获取真实新闻，帮助你提升宏观信息、投资研究和内容创作的理解能力。需要临时查证时，它还可以按你的明确问题调用 Tavily 搜索公开资料，或从你指定的公开网页抽取证据。

它不是 OpenBiliClaw 的皮肤、插件或官方版本。部分架构、交互和代码依据开源许可改编，来源说明只保留在 `LICENSE`、`NOTICE` 和“关于新闻爪”里；OpenBiliClaw 不是新闻爪的主页、客服、更新渠道或新闻服务。

新闻爪也不是量化交易系统：不接券商、不自动下单、不输出买卖、仓位、目标价等交易指令。

## 2. 每天最简单的使用方式

1. Windows 登录后，新闻爪后端按当前设置自动启动并在后台刷新。
2. 打开桌面 Web 或 DSH 右侧栏，先看“推荐”和“惊喜推荐”。
3. 看到重要内容时打开原文；明确喜欢就点喜欢，不想再看就点不感兴趣或忽略。
4. 暂时没空读的内容放入“稍后读”，长期留存的内容放入“收藏”。
5. 对某条新闻看不懂时直接进入对话，让新闻爪解释影响链和后续观察点。
6. 每隔几天看一次“画像”，确认它理解的兴趣和避雷是否正确；手工修改永远优先于 AI 推断。

## 3. 四个入口

### 桌面 Web

完整入口：推荐、当前列表筛选、内容库、画像、对话、消息、后台状态和设置。正式地址为 `http://127.0.0.1:8430/web`。

### 手机 Web / PWA

适合手机阅读和下拉刷新，显示在线、降级或离线状态。它与桌面端共用同一个后端、数据库和画像。

正式启动当前只监听本机 `127.0.0.1`，因此电脑端“手机访问”会明确显示暂不可用，不会生成一个实际打不开的二维码。只有把后端监听地址改为 `0.0.0.0`、确认 Windows 防火墙放行并启用访问保护后，局域网手机才能通过二维码或复制链接访问。

### 浏览器扩展

只是本机新闻爪的浏览器侧栏客户端。它只允许连接 `127.0.0.1` 或 `localhost`，不注入新闻网站、不读取 Cookie、不抓取页面。

### DeepSeek Harness 侧栏

在 Harness 会话区右侧显示新闻爪。默认宽 380px，可调 280–560px，并尽量为主会话区保留至少 400px。它还向 Agent 提供 24 个新闻爪工具，用于读推荐、提交反馈、查看画像、对话、管理本地收藏和按需研究。

## 4. 页面功能

### 推荐

- 展示媒体、技术提供方、发布时间、原文地址和证据级别。
- 有真实新闻封面时继续显示封面；无封面时显示“主题、故事、时效、证据”信息标签，不再把标题或正文重复放进图片位置。
- 桌面首页采用“左侧推荐队列 + 右侧分析详情”：队列只保留优先级、主题、标题、来源、时间和证据等级，避免把每张小卡做成迷你详情页；选择一条后，右侧再按需展示为什么推荐、可能影响链和后续观察点。
- “优先关注 / 值得关注 / 常规参考 / 探索观察”由用户匹配、证据完整度、时效和事件影响共同计算，并在当前待处理候选池（最多 1000 条）中按这个结果真实排列队列；它不再只是匹配置信度的另一种叫法。“标题级 / 摘要级 / 正文级”只回答证据完整度，高优先级也不等于事实已经被完全证实。
- 桌面端的主筛选按当前已加载新闻的类别展开，媒体来源放在右侧独立筛选；手机端显示前三个标签，更多标签以 `+N` 收起。
- 选择新闻打开右侧详情不会被记录成阅读、喜欢或画像信号；点击“阅读原文”才形成弱打开信号，喜欢、不感兴趣、忽略或评论才形成明确反馈。
- “换一批”重新取推荐，“继续加载”追加内容。开启滚动自动加载时，只有你真实滚动左侧队列到底部才追加一次；新增内容后必须离开底部再滚回来，不会在你没操作时把几百条内容自动灌进页面。
- 每个“后续观察点”都可加入本地持续跟踪，也可以停止跟踪。它保存的是“以后要关注什么”和当时判断，不会因为点一下就自动改变画像，也不代表后台已经完成查证。
- 顶部输入框只筛选当前已经加载的推荐，不是全库搜索或互联网搜索，也不会把关键词写进画像。

### 惊喜推荐

用于在稳定兴趣之外保留一定探索。桌面端把当前惊喜作为“今日首选”放进同一判断工作台，不再单独占用一整块重复标题和正文。无真实封面时左侧显示标签信息板，已采集的原始正文默认折叠，需要核对时再展开。选择详情本身不学习；阅读原文才作为弱打开信号，喜欢、不喜欢和忽略是更明确的信号。

### 内容库

包含收藏、稍后读和最近阅读。收藏与稍后读只保存在本机，不会修改媒体账号里的收藏，也不会自动强化画像。新记录会尽量保留当时的标签、优先级、推荐原因、影响链和观察点；以后算法变化，历史页仍显示当时判断。旧记录没有这些快照时仍可打开，但不会伪造不存在的历史分析。

### 五层画像

1. **事件**：打开、喜欢、不喜欢、忽略、评论和对话等事实。
2. **偏好**：喜欢什么、避开什么。
3. **觉察**：最近兴趣发生了什么变化。
4. **洞察**：系统对变化原因形成的、带证据的假设。
5. **灵魂**：较稳定的认知风格和价值取向。

手工修改的兴趣和避雷优先级最高。AI 推断必须带证据和置信度，用户可确认、拒绝或删除。

### 对话与探测

可以围绕某条新闻继续追问，也可以讨论系统提出的兴趣或避雷猜测。对话和探测结果会持久保存；明确确认的方向可进入画像。

### 消息与后台动态

消息包括惊喜推荐、待处理推荐、兴趣确认、避雷确认和画像猜测。后台动态显示来源抓取、刷新、学习和降级情况。

## 5. 证据等级

- **标题级**：只取得标题，AI 必须明确说“标题级信息”。
- **摘要级**：取得来源提供的摘要，可做有限解释。
- **正文级**：取得合同允许使用的正文，可做更完整的影响链分析。

没有正文时，新闻爪不得假装读过全文。

## 6. 哪些动作会让它更懂你

| 动作 | 会影响画像 | 说明 |
|---|---|---|
| 打开推荐 | 是 | 只作为弱信号，不能单独证明长期偏好 |
| 喜欢 / 不感兴趣 | 是 | 明确正负反馈 |
| 忽略 / 评论 | 是 | 用于出池和理解原因 |
| 对话 / 兴趣探测 / 避雷探测 | 是 | 明确结论可进入画像 |
| 收藏 / 稍后读 | 否 | 当前只进入本地内容库 |
| 顶部筛选词 | 否 | 当前只过滤已加载卡片 |

重复点击会用稳定的 `request_id/event_id` 去重，不会重复学习同一个动作。

## 7. 新闻来源配置

首批内置来源：

- Tushare `news`：财经快讯，多家主流财经媒体。
- Tushare `major_news`：长篇财经新闻。
- Tushare `cctv_news`：央视新闻联播文字稿。
- 国家统计局“最新发布”RSS。
- 国家统计局“数据解读”RSS。
- 人民网“全部新闻”RSS。
- 用户自己添加的官方 RSS/Atom。

每个 RSS 媒体在设置页各有一张独立卡片和独立开关；保存一个媒体的开关不会批量覆盖其他 RSS 来源。

### 真正生效的来源操作

- 启用或停用来源：下一轮刷新生效。
- 保存 Tushare Token：保存在新闻爪私有运行目录，页面只显示“已配置”，不会回显原值；下一次验证或刷新立即使用。
- 验证全部来源：逐接口检查权限、限流、超时、空结果和正文缺失。
- 添加或删除自定义 RSS：立即保存。
- 立即刷新新闻：创建一轮真实刷新任务。

### 当前暂不生效的来源字段

单来源“权重”和“独立刷新频率”目前尚未参与排序和调度，因此界面暂时隐藏。现在所有启用来源由全局热门/探索时钟统一调度。

Tushare Token 存在不等于三个新闻接口都有权限，必须点“验证全部新闻源”看每个接口的结果。

## 8. Tavily 按需研究

Tavily 不是新闻源，也不会按后台时钟自动抓取。Phase 1 的研究交互入口只有 DSH Agent 工具和后端 REST/Agent Bridge；桌面 Web 只管理 Key 和验证连接，不提供研究输入框或结果历史页，手机/PWA 与浏览器扩展也没有新增研究按钮、不会持有 Key。通过可用入口明确提出问题后，它适合两类场景：

1. **搜索公开证据**：例如“最近一周 AI 基础设施有哪些关键变化？”
2. **核对指定网页**：给出 1–3 个公开网页，让它只抽取与问题有关的片段。

默认 Search 使用低成本 `basic` 模式并固定 `chunks_per_source=1`，返回 5 条、最多 8 条；不会请求 Tavily 的成品答案、搜索 raw content 或图片。Extract 必须同时提供问题和 1–3 个公开 `http(s)` URL，每个来源默认取 2 个、最多 3 个片段。localhost、内网地址、带账号密码的 URL 和明显包含邮箱、手机号、本机路径或密钥的问题会被拒绝，不会发往外部服务。

### 配置 Tavily Key

- 在电脑端新闻源设置页找到 **“Tavily 按需研究（不是新闻源）”**。卡片明确提醒：查询和公开 URL 会发送给 Tavily；私人资料、邮箱、手机号、本机路径和任何密钥都不得输入。
- 保存 Tavily API Key 后，Key 只进入新闻爪本机后端的私有运行目录；调用 Tavily 时只用于鉴权，不会混入查询正文或 URL。页面只显示“已配置”和固定掩码，不展示、不回显原值或尾部。
- “验证连接（不消耗搜索额度）”会让本机后端使用 Key 调用 Tavily 官方 `GET /usage`，真实检查网络、Key、权限和额度；它不发送研究查询或 URL、不创建研究记录、不消耗搜索 credit。成功响应可包含脱敏的 `key_usage`、`key_limit`、`account_plan`、`plan_usage`、`plan_limit`，Key 本身仍不会展示或回显。
- 也可以用 `TAVILY_API_KEY` 环境变量作为回退；本地保存值优先。
- 删除本地 Key 后，如果环境变量仍存在，Tavily 仍会显示可用。
- 不要把 Key 粘贴进聊天、DSH 工具参数、截图、源码或日志。
- 研究查询和 URL 本身也会发送给 Tavily，因此不得包含私人资料或任何凭据。

### 本地历史与缓存

研究问题、provider 请求号、证据片段和来源 URL 保存在独立的 `newsclaw_research.db`。general 缓存 24 小时、news 30 分钟、finance 15 分钟；同样的问题在新鲜期内优先读本地，不重复消耗 Tavily。显式“刷新”只绕过缓存，不删除旧研究记录。

研究记录是“外部世界证据”，不是“用户偏好记忆”：它不会自动改变五层画像，不会进入新闻候选池或推荐池，也不会因为你搜索过某个词就认定你长期喜欢它。模型如果继续分析，仍应保留来源 URL，并区分来源事实和自己的推断。

## 9. 推荐的运行配置

| 设置 | 当前建议 | 用途 |
|---|---:|---|
| 候选池目标数 | 300 | 保证每天有足够内容，避免池子过大增加成本 |
| 调度检查间隔 | 10–30 分钟 | 只检查哪个刷新通道到期 |
| 热门刷新 | 30 分钟 | 获取最近 24 小时新闻 |
| 探索刷新 | 360 分钟 | 从最近 7 天补充跨主题内容 |
| 反馈积累阈值 | 3 | 兼顾学习速度与防止一次误点带偏 |
| 主动推送 | 开 | 准备惊喜推荐和待确认探测 |
| 后台 AI | 开 | 生成解释、画像和探测 |
| 浏览器关闭后 | 继续 | 浏览器关掉后仍持续整理 |
| 最大重试次数 | 3 | 单来源临时失败时自动恢复 |
| 初始 / 最大退避 | 1 / 30 秒 | 避免连续撞限流 |

热门和探索同时到期时，系统会优先执行超期更久的通道，避免探索长期排不到。

## 10. AI 模型配置

当前默认使用一个 DeepSeek 实例：并发 4、单请求最长 1200 秒，画像、发现、推荐和评估默认继承同一调用链。

- **模型实例**：填写服务商、模型、Base URL 和 API Key。
- **默认调用链**：决定普通 AI 任务先用哪个实例、失败后是否切换备选。
- **模块调用链**：可让画像、发现、推荐和评估分别使用不同实例；普通使用保持“继承默认”最稳。
- **Embedding**：用于本地语义能力；模型输出维度必须与配置一致。

API Key 只保存在本机凭据配置中，页面只显示脱敏状态。不要把 Key 贴进对话、截图或日志。

## 11. 哪些设置需要重启

| 配置 | 生效方式 |
|---|---|
| 新闻源开关、RSS、新闻刷新、热门/探索节奏 | 保存后热生效 |
| AI 实例与调用链 | 保存后进入热重载，通常无需重启 |
| 主题、色相、滚动加载、惊喜数量 | 当前浏览器立即生效 |
| Tushare Token | 下一次验证或刷新立即使用 |
| Tavily API Key | 下一次研究请求立即使用 |
| 数据目录 | 必须完整退出并重启；新目录看起来像一个全新系统 |
| DSH 插件 `apiUrl` / `timeoutMs` | 重新加载插件或重启 Harness 最稳妥 |

SQLite 文件位置由“数据目录”自动决定。界面中的数据库路径为只读兼容信息，不单独修改。

### DSH 设置页

DSH 侧栏里的设置页只展示三类真实信息：运行状态、新闻来源、插件连接。它不会再通过旧配置接口假装修改 AI、新闻源、推荐或画像。需要调整完整业务配置时，点击“打开电脑端”进入正式桌面 Web。

- `apiUrl`：插件与 24 个 Agent 工具共同使用的后端地址，正式保持 `http://127.0.0.1:8430`。
- `timeoutMs`：单个 Agent 工具最长等待时间，推荐 `300000` 毫秒。
- 开机自启动：这是 DSH 设置页唯一保留的写入项，真实修改 NewsClaw 本机自启动状态。
- 修改 `apiUrl` 或 `timeoutMs` 后，重新加载插件或重启 Harness 最稳妥。

## 12. DSH 的 24 个 Agent 工具

### 推荐与状态

下列名称在 Harness 中都带 `newsclaw_` 前缀，例如 `newsclaw_get_capabilities`。

`get_capabilities`、`get_runtime_status`、`get_activity_feed`、`get_source_availability`、`recommend`、`reshuffle`、`append_recommendations`。

### 反馈与惊喜

`submit_feedback`、`get_spotlight`、`respond_spotlight`。

### 对话与探测

`chat`、`get_chat_history`、`next_probe`、`respond_interest_probe`、`next_avoidance_probe`、`respond_avoidance_probe`。

### 画像与内容库

`get_profile`、`get_profile_edit_state`、`edit_profile`、`save_local`、`remove_saved`、`list_saved`。

### 按需研究

`newsclaw_search_web`、`newsclaw_extract_evidence`。

`newsclaw_search_web` 接受问题、`general|news|finance` 主题、可选时间范围和最多 8 条结果；`newsclaw_extract_evidence` 接受问题、1–3 个公开 URL 和每来源最多 3 个片段。两个工具都可显式要求刷新本地缓存，但都不会修改画像、收藏或推荐池。DSH 插件不保存 Tavily Key，实际调用和缓存都由本机 NewsClaw 后端负责。

写操作会携带稳定的 request ID，同一动作重试不重复学习。Agent 输出会递归遮蔽常见 Token、Key 和 Authorization 字段。

## 13. 状态怎么读

- **在线**：所有已启用来源与核心能力正常。
- **降级**：至少一个来源失败，但其他来源和已有推荐仍可用。
- **离线**：本机后端无法连接。
- **本轮无数据**：来源可访问，但该时间窗口没有新内容，不等于 Token 错误。
- **无接口权限**：Token 存在，但该 Tushare 新闻接口没有单独开通。

单来源失败不会把整轮伪装成成功，也不会清空已有推荐。

## 14. 隐私、许可与边界

- 默认仅供本人本机、非商业使用。
- 定时新闻采集不抓网页、不读 Cookie、不注入新闻网站；Tavily Extract 只处理用户明确给出的 1–3 个公开 URL。
- 浏览器扩展只连接本机地址。
- Tushare 个人许可限定个人、不可转让、非商业用途；公开或收费前必须另取机构与内容展示授权。
- OpenBiliClaw 的来源声明依法保留在许可文件与“关于新闻爪”中，但不承担新闻爪的主页、客服、更新或服务角色。
